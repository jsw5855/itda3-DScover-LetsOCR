## 0. 배경 (AI 참고용 요약)

- 과제: 상품 포장 사진에서 소비기한을 뽑아 `year, month, day, final_date`로 출력합니다. 읽을 수 없는 칸은 `NONE`입니다.
- 파이프라인(예선 최종본 `main 39e1892`, `ocr_pipeline.predict_image`)
  - 검출 모델: `PP-OCRv6_medium_det`, 인식 모델: `korean_PP-OCRv5_mobile_rec`, CPU 전용, `text_det_box_thresh=0.7`
  - 4단계 cascade: `original_512` → `rotation_270` → `highres_1024` → `clahe`
  - 각 단계에서 Parser가 날짜 후보를 하나라도 찾으면 그 단계에서 멈춥니다. 네 단계 모두 후보가 없으면 첫 단계 결과를 씁니다(`original_no_candidate`).
  - 제출 시간 제한 때문에 후보가 나오면 바로 멈추는 구조입니다.
- 데이터: 라벨이 있는 701장. 예선 최종본으로 실제로 돌려서 **모든 단계의 OCR 원문을 저장**했습니다.
- Parser 개선 후(claude 브랜치 `date_parser`, 저장된 OCR 원문으로 재채점): **579/701 = 82.60%**
  - 예선 최종본은 538/701 = 76.75%였습니다.
  - 남은 오답 122장 중 **OCR 문제 99장**을 이 문서에 정리했습니다.
  - 나머지 23장은 Parser 보류 또는 라벨 확인 대상이라 제외했습니다.

## 1. 분류 기준

- **OCR 문제**: 저장된 OCR 원문 어디에도 정답 날짜가 온전하게 없는 경우입니다. 글자를 못 찾았거나, 잘못 읽었거나, 일부만 읽은 경우가 해당합니다.
- **Parser 문제(제외)**: OCR 원문에 정답이 온전히 있는데 Parser가 해석하지 못한 경우입니다.
- 사진마다 저장된 모든 단계의 원문을 사람이 확인해서 유형을 정했습니다.

## 3. cascade 관점에서 본 점 (참고)

- **99장 중 26장은 1단계(`original_512`)에서 틀린 날짜나 일부만 있는 날짜로 멈췄습니다.** 뒤 단계는 실행되지 않았습니다.
  - D2 13장, D5 5장, D3 5장, D4 2장, D1 1장입니다.
  - 이 사진들은 고해상도 등 뒤 단계였다면 맞게 읽었을지 **아직 모릅니다**(저장된 원문이 없음).
  - 확인하려면 이 26장만 4단계를 모두 돌려보면 됩니다. 필요하면 대상 목록을 드리겠습니다.
- **D1 40장 중 38장은 4단계를 모두 돌렸는데도 날짜 줄이 없었습니다.** 검출 단계 쪽 과제로 보입니다(점 인쇄, 곡면, 작은 글씨, 반사).
- D6(965)는 "1단계 결과가 틀려도 멈추는" 구조 때문에 놓친 사례입니다. 고해상도가 이미 정답을 읽었습니다.
- Parser 개선으로 1단계에서 끝나는 사진이 늘었습니다. 다음 단계로 넘어가는 사진이 153장에서 124장으로 줄었습니다. **OCR·cascade 실험은 새 Parser(claude 브랜치 `date_parser`) 기준으로 하는 게 맞습니다.**

## 4. CSV 칸 설명 (`ocr_issues_v6.csv`)

| 칸 | 내용 |
|---|---|
| `image_id`, `file_name` | 대회 이미지 번호와 파일명 (`상품사진입니다` 폴더) |
| `type` | 위 D1~D6 |
| `truth` | 정답 (`labels_701.csv`, 2026-09-26 수정본) |
| `prediction`, `cascade_result_stage` | 새 Parser 기준 현재 예측과 멈춘 단계 |
| `stages_run` | 실행된 단계 수 (1~4) |
| `ocr_original_512` ~ `ocr_clahe` | 각 단계 OCR 원문 중 **날짜와 관련 있어 보이는 줄만** (숫자 패턴, 영문 월, EXP·BEST·까지·기한). 실행 안 된 단계는 그렇게 표시 |
| `label_source` | 정답 출처. `approved`는 검수 확정, `candidate`는 미검수. `existing_300`은 우리 팀, `incoming_432`는 다른 팀 |
| `labeler_note` | 예선 때 라벨 작성자 메모 (기존 300장만) |

## 5. 주의

- OCR 원문은 이수민 PC(Windows, CPU)에서 예선 최종본으로 돌린 결과이고, 기존 300장은 9/23 예선 재현 기록과 예측이 모두 같았습니다.
- 정답 99장 중 89장은 **미검수 라벨**이라, 일부는 라벨이 틀렸을 수 있습니다. 이번에 라벨 오류 6장을 찾아 이미 고쳤습니다. OCR 원문과 정답이 너무 다르면 이미지를 먼저 확인해 주세요.
- 이미지 파일은 포함하지 않았습니다. 대회 이미지 폴더에서 `file_name`으로 찾으면 됩니다.
- 전체 OCR 원문(모든 박스, 좌표, 신뢰도 포함)은 claude 브랜치 `docs/run701/ocr_dump.jsonl`에 있습니다.
