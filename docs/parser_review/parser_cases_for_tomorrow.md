## 1. 확정 사례: 검수 58장 중 Parser 문제 21장

### A. 연도 없는 월.일 (`MM.DD`) 미지원: 15장 + 오답 1장

| 사진 | 인쇄 | 정답 | 현재 |
|---|---|---|---|
| 106 | `10:20 13:53` | NONE-10-20 | NONE |
| 763 | `11.12 05시F2` / `EPC5` | NONE-11-12 | NONE |
| 789 | `12.19 D1758` | NONE-12-19 | NONE |
| 994 | `02.18까지` / `15:49.F1A` | NONE-02-18 | NONE |
| 1070, 1071 | `01.24 A` | NONE-01-24 | NONE |
| 1131 | `유통기한` / `02.12.12:53.HA` / `까지` | NONE-02-12 | NONE |
| 2051 | `유통기한 04.14 까지` / `Expiry Date 13:45 JK` | NONE-04-14 | NONE |
| 2159 | `04.13 D0932` | NONE-04-13 | NONE |
| 2265 | `03.05 10:14까지 C2` | NONE-03-05 | NONE |
| 2310 | `03.13. 13:47 까지 F5` / `03.01. 13:47 부터 A` | NONE-03-13 | NONE |
| 2345 | `02.12까지 12C52D` | NONE-02-12 | NONE |
| 2927, 2928 | `04.08` / `R0744` / `유통기한` | NONE-04-08 | NONE |
| 3277 | `세종 04.05` | NONE-04-05 | NONE |
| **824** | `유통기한 12.18. 10:41 F5` / `제조일자 12.06. 10:41 D1` / `까지` | NONE-12-18 | **2018-12-10 (오답)** |

- 대부분 한국 유제품(요거트·우유)입니다. `MM.DD` 뒤에 시각(`10:14`, `13:47`), 라인 코드(`F5`, `D1758`), `까지`가 붙습니다.
- 824: `12.18. 10`을 세 칸짜리 날짜로 묶어 2018-12-10을 만들었습니다. **시각의 시(hour)가 날짜 칸으로 들어가는 문제**입니다.
- 106: 월.일 구분자가 `:`(`10:20`)라 시각과 구분이 어렵습니다. 뒤에 진짜 시각(`13:53`)이 따로 있다는 점이 단서입니다.

**수정 방향**
- 두 자리.두 자리(`MM.DD`, `MM:DD`) 패턴을 추가하고 year=NONE으로 둡니다.
- 오탐을 막는 조건:
  - 월 1~12, 일 1~31, 달력상 유효한 날짜만
  - 뒤에 단위(`g`, `mg`, `%`, `kcal`, `ml`, `mL`)가 붙으면 제외 (영양성분 `3.6g` 등)
  - **같은 사진에 완전한 날짜(연도 포함) 후보가 있으면 쓰지 않음**
  - `:` 구분 형태는 바로 뒤에 다른 `HH:MM`이 있을 때만 날짜로 인정 (106)
- 시각 보호: 숫자 칸 바로 뒤에 `:숫자`가 오면 날짜 칸으로 쓰지 않습니다 (824).
- 부터/까지가 같이 있으면 `까지` 쪽을 선택합니다. `부터`를 제외 키워드에 추가 (2310, 824의 `제조일자`는 기존 키워드로 처리).

**위험**: 가장 큰 변경입니다. 영양정보·가격·버전 번호 오탐 여부를 701장 OCR 원문으로 꼭 확인해야 합니다.

### B. 형식 안내 문구 미활용: 2장

| 사진 | 인쇄 | 정답 | 현재 |
|---|---|---|---|
| 1205 | `05.21 L095 2` / `Mindestens haltbar bis Ende: Monat/Jahr` | 2021-05-NONE | NONE |
| 2917 | `30/04/21` / `CH 2371` / 한글표시 `(읽는법: 일,월,년순)` | 2021-04-30 | **2030-04-21 (오답)** |

**수정 방향**: 같은 사진의 글자에서 형식 안내(`Monat/Jahr`, `MM/YY`, `월/년`, `일,월,년`, `DD/MM/YY`, `Month/Year`)를 찾아서 해당 순서로 해석합니다. 안내가 없으면 기존 규칙을 그대로 씁니다. **위험 낮음.**

### C. 2자리 연도 순서: 1장 (보류 권장)

| 사진 | 인쇄 | 정답 | 현재 |
|---|---|---|---|
| 2034 | `17.12.20` / `L352MW-- 12:14` | 2020-12-17 | 2017-12-20 |

- 근거가 로트번호(L352 = 352번째 날)뿐이라 일반 규칙으로 만들기 어렵습니다. 이번에는 제외합니다.

### D. 실패한 패턴이 진짜 날짜를 가림: 1장 (+ 기존 오답 1장)

| 사진 | 인쇄 | 정답 | 현재 |
|---|---|---|---|
| 515 | `201045 46 +U 2026. 01` | 2026-01-NONE | NONE |

- 문자 `U`를 숫자 0으로 보는 규칙 때문에 `U 2026. 01`이 먼저 날짜 모양으로 잡힙니다. 그런데 해석이 실패하고도 그 자리를 차지해서, 뒤의 `2026. 01`(연.월 패턴)이 시도되지 않습니다.
- **수정 방향**: 해석 가능한 후보가 하나도 없는 매칭은 자리를 차지하지 않게 합니다. **위험 낮음.**

### E. 월/2자리 연도: 1장 (보류 권장)

| 사진 | 인쇄 | 정답 | 현재 |
|---|---|---|---|
| 2586 | `Batch No: 652332` / `Exp.Date: 12/22` | 2022-12-NONE | NONE |

- `12/22`는 12월 22일로도 읽힙니다. 형식 안내가 없으면 판단 근거가 약해서 제외합니다. B에서 안내 문구가 있을 때만 처리합니다.

## 2. 추가 후보: 기존 300장 오답 (예선 중간 v5 OCR 원문 기준, 701장 실행 후 v6 원문으로 확인)

| 사진 | 정답 | v5 시절 OCR 원문 | 원문을 넣었을 때 현재 Parser | 문제 |
|---|---|---|---|---|
| 893 | 2022-02-07 | `07FEB2022 PV 07:17 2` | NONE | 일+영문월+연도가 붙은 `DDMONYYYY` 패턴 없음 |
| 2251 | 2021-05-09 | `09MAY2021` | NONE | 위와 같음 |
| 2247 | 2021-09-07 | `유통기한:` / `20 21.09.07` / `까지` | 2020-09-21 | 연도가 `20 21`로 끊겨 엉뚱하게 조합 |
| 2011 | 2020-06-30 | `2020.C6.30` | NONE | 문자 `C`를 숫자 0으로 보지 않음 |
| 2726 | 2022-03-17 | `L0076 17.03.22` / `04:55` | NONE | D와 같은 문제 (`0076 17`이 자리를 먼저 차지). 이것만 고치면 2017-03-22가 나옴 → 2자리 연도 순서(DD.MM.YY) 문제도 남음 (C와 같이 보류) |
| 2278 | 2023-07-NONE | `BY JUIL` \| `2023` (박스 분리) | NONE | 월과 연도가 다른 박스로 분리 (+ OCR의 `JUIL` 오인식) |

- 박스 분리(2278): 같은 줄에 가까이 있는 박스를 합쳐서 한 번 더 추출하는 방안을 검토합니다.

## 3. 작업 순서 제안

1. **위험 낮은 것부터**: D(자리 차지 문제, 515) → B(형식 안내) → 시각 보호(824) → `DDMONYYYY` 패턴(893, 2251)
2. **A(연도 없는 월.일)**: 조건을 붙여서 구현합니다. 오탐 확인이 핵심입니다.
3. 매 수정마다 다음을 확인합니다.
   - 기존 테스트 통과: date_parser 테스트 87개 포함 전체 122개. 이 중 5개는 로컬 `data/`, `labels/labels_300.csv`가 필요해서 해당 파일이 없는 환경에서는 main에서도 실패함
   - 위 사례를 테스트로 추가 (`printed_text_58.json`의 인쇄 글자 → 정답)
   - `build_parser_cases.py`를 다시 돌려 21장 중 몇 장이 해결됐는지 확인
4. **701장 OCR 원문이 오면**: 저장된 원문으로 수정 전/후를 비교합니다.
   - 같은 표본(seed 42)을 씁니다.
   - 새로 맞힌 사진과 새로 틀린 사진 목록을 모두 확인합니다.
   - OCR은 다시 돌리지 않습니다.
5. 최종 후보만 전체 데이터로 검증하고, 정선우 님에게 통합을 요청합니다.

## 4. 예상 효과 (검수 58장 기준, 인쇄 글자 입력)

| 묶음 | 해결 예상 |
|---|---|
| A 연도 없는 월.일 | 16장 |
| B 형식 안내 | 2장 |
| D 자리 차지 | 1장 |
| C, E (보류) | 0장 (2034, 2586 남음) |
| **합계** | **21장 중 19장** |

실제 성능 향상은 OCR이 글자를 제대로 읽는지에 달려 있습니다. 그래서 701장 OCR 원문으로 다시 측정해야 합니다.
