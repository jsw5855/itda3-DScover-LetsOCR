## 1. 개선 대상: 8개 묶음, 47장

아래 예시 글자는 **예선 v6 OCR이 실제로 읽은 원문**입니다. 장수는 원문상 해결 가능한 최대치이고, 실제 개선 폭은 구현 후 재현 도구로 측정합니다.

| # | 대상 | 장수 | 예시 (OCR 원문 → 현재 결과) | 위험 |
|---|---|---:|---|---|
| T1 | **형식 안내 문구 활용** ("읽는법: 일,월,년순", "Monat/Jahr") | 2 | 2917 `30/04/21` → 2030-04-21 | 낮음 |
| T2 | **날짜에 붙은 시각·다른 날짜 분리** | 5 | 682 `2026.01.2512:42` → NONE, 824 `12.18. 10:41` → 2018-12-10, 686 `2025.10.032025.10.12까지` | 낮음 |
| T3 | **일(day) 뒤에 붙은 잡음 숫자**: 세 자리 일이면 앞 두 자리 사용 | 5 | 1730 `2021.10.028` → 2021-10-28 (정답 10-02), 1741 `2022. 11.013` | 중간 |
| T4 | **구분 기호·문자 보정** (`·`, `×`, `X`, 쉼표, `C`→0, 붙은 `MMYYYY`·`DDMMYYYY`) | 15 | 913 `2021·10.19`, 2731 `18×04>2021`, 2011 `2020.C6.30`, 3203 `EXP 102021`, 715 `EXP:2606-2026` | 낮음~중간 |
| T5 | **붙은 영문 날짜** (`DDMONYYYY`, `DDMONYY`) | 6 | 893 `07FEB2022`, 1757 `09MAR2023`, 2048 `31JUL21` → NONE | 낮음 |
| T6 | **해석 실패한 매칭이 진짜 날짜를 가림** | 1 | 515 `+U 2026. 01` | 낮음 |
| T7 | **연도 없는 월.일** (`MM.DD`, 점 구분만) | 11 | 1070 `01.24 A`, 2345 `02.12까지`, 2310 `03.13.13:47` → NONE | 중간 |
| T8 | **제조일·산란일 등 다른 날짜 선택** | 2 | 2066 산란일자 선택, 2247 `20 21.09.07`(연도가 끊김) | 중간 |
| | **합계** | **47** | 현재 오답 169장 중 | |

### 위험 확인 결과 (재현 도구로 측정)

- **T7 연도 없는 월.일**
  - 지금 정답인 사진 중, 1단계 글자에 월.일 모양이 있어 cascade가 너무 일찍 멈출 위험이 있는 사진은 4장입니다(432, 1793, 2408, 2831).
  - 이 중 3장은 `07:24` 같은 **콜론 시각**입니다. 그래서 **점(`.`) 구분만 허용**하고, 콜론 형태(106 `10:20`)는 보류합니다.
  - 남은 위험은 432 한 장입니다. 구현 후 실제로 측정합니다.
- **T1이 T7보다 먼저 적용돼야 합니다.** 그래야 1205(`05.21` + Monat/Jahr)를 5월 21일이 아니라 2021년 5월로 읽습니다.

라벨이 틀린 것으로 확인되면, 수정해서 선우님께 전달하고 정답 파일을 갱신합니다.

## 4. 주의: "후보값 639장"의 실제 구성 (정정)

앞서 "639장은 두 팀 라벨이 일치한 후보값"이라고 설명했는데, **사실과 다릅니다.**

| 구성 | 장수 |
|---|---:|
| 기존 300장 라벨만 있음 | 251 |
| 다른 팀 432장 라벨만 있음 | 362 |
| 두 팀 라벨이 있고 서로 일치 | 26 |

즉 **613장은 한 팀 라벨만 있고 교차 확인되지 않았습니다.** 3번의 라벨 의심 사례가 모두 여기서 나왔습니다. 701장 정확도를 공식 수치로 쓸 때 이 점을 같이 밝혀야 합니다.

## 5. 작업 순서와 통과 기준

1. **라벨 확인 7장** (본인이 이미지 확인) → 정답 파일 갱신
2. **위험 낮은 것부터 구현**: T6 → T1 → T2 → T5 → T4 → T3 → T8 → T7
3. **묶음마다 확인할 것**
   - 기존 테스트 통과 (date_parser 87개 포함 전체 122개. 로컬 데이터가 필요한 5개 제외)
   - 해당 사례를 테스트로 추가
   - 재현 도구로 701장 비교: **새로 맞힌 사진과 새로 틀린 사진 목록을 모두 기록**
   - 새로 틀린 사진이 생기면 원인을 확인하고, 이득보다 손해가 크면 규칙을 좁히거나 되돌림
   - 다음 단계로 넘어가는 사진 수(속도 영향)도 기록
4. 최종 후보를 전체 데이터로 확인한 뒤 선우님께 통합 요청
