## 측정 방법
- 예선 최종본으로 701장을 실제로 돌려 저장한 OCR 원문(`docs/run701/ocr_dump.jsonl`)에 새 Parser를 다시 돌렸습니다(`scripts/replay_parser.py`).
- 예선의 4단계 cascade를 그대로 재현합니다. 수정 전 코드로 돌리면 실제 실행과 701장 모두 같은 결과가 나오는 것을 확인했습니다.
- OCR 모델, 전처리, cascade 코드(`ocr_pipeline.py`)는 바꾸지 않았고, `date_parser/`만 수정했습니다.
- 정답은 `labels_701.csv`(검수 확정 69장 + 후보 632장)입니다.

## 남은 Parser 문제 (보류)
- 2034 `17.12.20`, 1862 등: 2자리 연도의 일.월.년 순서. 안내 문구 없이는 한국 제품과 구분 불가
- 143, 844, 1035, 2829: 4자리 연도의 월/일 순서. 다른 팀 라벨 단독이라 라벨 확인이 먼저 필요
- 2066: 멀리 있는 코드(`4.24-5-1625`)가 날짜로 읽혀 "더 늦은 날짜" 규칙으로 선택됨. 후보 선택 순서를 바꿔야 해서 영향 범위가 큼
- 2586 `12/22`, 106 `10:20`(콜론 월일), 3011 `1112 2021`(키워드 없는 붙은 숫자)
- 1227: 라벨 확인 필요(두 날짜 중 더 이른 날짜가 정답으로 기록됨)

## 주의
- **개선 대상을 이 701장의 오답에서 골랐기 때문에, 같은 701장으로 잰 +41은 실제보다 좋게 나올 수 있습니다.** 다만 매 단계 새로 틀린 사진이 0장이었고, 규칙은 사진 번호가 아니라 글자 형식으로 만들었습니다.
- 후보 632장 중 606장은 한 팀 라벨만 있어 교차 확인되지 않은 정답입니다.
- 실제 제출 조건(시간 제한)에서의 속도는 선우님 환경에서 한 번 확인이 필요합니다. 다음 단계로 넘어가는 사진이 줄었으니 느려질 가능성은 낮습니다.
