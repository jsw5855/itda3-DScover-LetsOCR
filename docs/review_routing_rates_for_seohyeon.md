# 서현에게: 직원 검토 비율 분석 결과 (도메인·ROI 파트용)

작성: 이수민 · 2026-09-27 · **초안** (최종 제출 코드가 확정되면 숫자가 조금 바뀔 수 있음)

## 1. 한 줄 요약

우리 OCR을 매장에 쓰면 **상품 10개 중 약 6.4개는 직원이 확인만 하고 승인**하고, **약 3.6개는 직원이 한 번 더 본다.**
그런데 3.6개 중 **처음부터 날짜를 직접 쳐야 하는 건 약 0.9개(100개 중 9.1개)**뿐이다. 나머지는 탭 한 번이나 눈으로 한 번 확인하는 수준이다.
그리고 확인만 하고 승인한 것 중 날짜가 틀린 경우가 **전체 100개 중 약 3.4개** 있고, 그중 **지난 상품이 통과할 수 있는 경우는 전체 100개 중 약 1.1개**다.

## 2. 무엇을 계산했나 (쉬운 설명)

OCR이 날짜를 읽으면, 결과를 믿을 수 있는 정도에 따라 직원 화면을 네 가지로 나눈다고 가정했다.

| 이름 | 언제 | 직원이 하는 일 | 상품 100개당 |
|---|---|---|---:|
| **수동 입력** (MANUAL) | 날짜 일부를 못 읽음 (예: 연도 없음) | 날짜를 직접 입력 | 16.7개 |
| **후보 선택** (CHOOSE) | 날짜가 2개 이상 읽힘 (예: 제조일과 소비기한) | 맞는 날짜를 고름 | 12.6개 |
| **재확인** (RECHECK) | 날짜는 하나인데 글자 인식 자신감이 낮음 (0.90 미만) | 사진을 보고 확인 | 7.3개 |
| **확인 후 승인** (CONFIRM) | 위에 해당 안 됨 | 보고 승인 버튼 | 63.5개 |

- **직원 검토 비율** = 수동 입력 + 후보 선택 + 재확인 = **36.5%**
- **확인 없이 넘어갈 위험** = "확인 후 승인"으로 갔는데 날짜가 틀린 경우 = **3.4%**

## 3. 핵심 숫자

| 지표 | 값 | 오차 범위 (95%) | 뜻 |
|---|---:|---:|---|
| 직원 검토 비율 | **36.5%** | 33.0~40.1% | 10개 중 약 3.6개는 직원이 직접 본다 |
| 확인 후 승인 비율 | 63.5% | 59.9~67.0% | 10개 중 약 6.4개는 승인만 누른다 |
| 승인했는데 날짜가 틀림 | **3.4%** | 2.3~5.0% | 100개 중 약 3.4개 |
| └ 실제보다 **늦은 날짜** (지난 상품 통과 위험) | **1.1%** | 0.6~2.2% | 100개 중 약 1개. 그중 절반은 7일 이내 차이 |
| └ 실제보다 **이른 날짜** (멀쩡한 상품 폐기) | 2.3% | — | 안전 문제는 아니고 손실 문제 |

"오차 범위"는 사진 701장으로 계산한 숫자라서 생기는 불확실성이다. 새 사진으로 다시 재면 대부분 이 범위 안에 들어온다는 뜻이다.

## 3-1. "36.5%는 너무 많지 않나?"에 대한 답: 직원 작업을 쪼개 보면

직원 검토 36.5%가 전부 같은 일이 아니다. 실제 작업으로 나누면 다음과 같다.

| 실제 직원 작업 | 상품 100개당 | 설명 |
|---|---:|---|
| **처음부터 날짜 직접 입력** | **9.1개** | OCR이 날짜를 아예 못 읽음 (64장) |
| 날짜 일부만 있음 → 보충 입력 | 7.6개 | 53장 중 **45장은 인쇄된 그대로 정확히 읽음**. 제품에 원래 일(day)이 없거나(연·월만 인쇄, 39장) 연도가 없음(월·일만 인쇄, 14장) |
| 후보 2개 중 하나 탭 | 12.6개 | 88장 중 **82장(93%)은 정답이 후보 안에 있음** |
| 사진 보고 맞는지 확인 | 7.3개 | 51장 중 **41장(80%)은 이미 정답** |
| **합계 (직원 검토)** | **36.5개** | |

- **비교 대상은 0%가 아니라 100%다.** 지금 매장은 모든 상품의 날짜를 사람이 직접 본다. 우리 방식은 약 64%를 승인만으로 끝내고, 직접 입력이 필요한 건 약 9%다.
- **일부러 보수적으로 설계했다.** 소비기한은 틀리면 안전 문제라서, 애매하면 사람에게 넘기도록 했다. 그래서 지난 상품이 확인 없이 통과할 위험이 1.1%로 낮다.
- **매장이 조절할 수 있다.** 재확인 기준을 낮추면 검토가 줄고 위험이 조금 는다(4절).
- **더 줄일 여지가 있다(향후 개선, 아직 계산 안 함).** 연·월만 있거나 연도가 없는 제품은 OCR이 정확히 읽은 것이다. 월말 날짜로 채우거나 가장 가까운 미래 연도를 붙이는 규칙을 넣으면 검토 비율을 더 낮출 수 있다.

※ "정확히 읽음"과 "이미 정답" 비율은 정답 라벨이 필요한 참고 수치다(대부분 미검수 라벨).

## 4. 기준을 바꾸면 (참고용, 실제 정책 아님)

"재확인"으로 보내는 기준(인식 자신감)을 바꾸면 **직원 부담과 위험이 반대로 움직인다.**

| 재확인 기준 | 직원 검토 비율 | 승인했는데 틀림 | 지난 상품 통과 위험 |
|---|---:|---:|---:|
| 0.85 (느슨하게) | 31.4% | 4.0% | 9장 |
| **0.90 (현재)** | **36.5%** | **3.4%** | **8장** |
| 0.95 (엄격하게) | 54.9% | 1.7% | 2장 |

매장이 안전을 더 중시하면 0.95처럼 기준을 올려서 위험을 줄일 수 있다. 대신 직원 확인이 약 1.5배 늘어난다.

## 5. ROI 계산에 바로 쓰는 법

상품 N개를 처리할 때:

```text
직원 시간 = N x (0.167 x 수동입력시간 + 0.126 x 후보선택시간 + 0.073 x 재확인시간 + 0.635 x 승인시간)
기존 방식 = N x 수동입력시간        (모든 상품을 사람이 보고 입력한다고 할 때)
절감률    = 1 - 직원 시간 / 기존 방식
위험 건수 = N x 0.011              (지난 상품이 확인 없이 통과할 수 있는 건수)
```

**예시 (시간 값은 가정)**: 수동입력 15초, 후보선택 5초, 재확인 5초, 승인 2초일 때
- 직원 시간 = 0.167×15 + 0.126×5 + 0.073×5 + 0.635×2 = 2.505 + 0.63 + 0.365 + 1.27 = **약 4.8초/개**
- 기존 방식 15초/개와 비교하면 **절감률 약 68%**
- 시간 값은 매장 실측이나 자료 조사로 바꿔 넣으면 된다.

## 6. 보고서에 쓸 때 꼭 같이 적을 조건

1. **데이터**: 식품 포장 사진 701장. 모델 개발 과정에서 본 사진이 섞여 있어서 새 사진에서는 조금 더 나쁠 수 있다.
2. **정답 라벨**: "틀림" 숫자는 대부분 미검수 라벨(632장) 기준이다. 검수 확정 69장에서는 승인했는데 틀린 사진이 4장이다.
3. **코드 기준**: 현재 제출 코드(main `bb83a74`) 기준. 최종 코드가 확정되면 다시 계산한다.
4. **분야 차이**: 화장품(작은 글씨, 둥근 용기, 영어 표기)이나 매장에서 찍은 사진에서는 비율이 다를 수 있다.
5. **OCR 재실행 없음**: 저장된 OCR 결과로 계산했다.

## 7. 보고서에 그대로 넣을 수 있는 문장

> 식품 포장 사진 701장에 현재 제출 파이프라인을 적용하면, 결과의 63.5%는 직원이 확인만 하고 승인할 수 있고 36.5%(95% 신뢰구간 33.0~40.1%)는 직원 검토로 분류된다. 검토 유형은 수동 입력 16.7%, 후보 선택 12.6%, 재확인 7.3%다.

> 직원 검토로 분류되는 36.5% 중 날짜를 처음부터 입력해야 하는 경우는 9.1%다. 나머지 27.4%는 두 후보 중 하나를 고르거나(12.6%), 이미지를 한 번 확인하거나(7.3%), 인쇄되지 않은 일부 날짜를 보충하는(7.6%) 가벼운 작업이다. 후보 선택 경로에서는 93%가 정답 후보를 포함한다.

> 확인만 하고 승인하는 결과 중 날짜가 틀린 경우는 전체의 3.4%(2.3~5.0%)다. 그중 실제보다 늦은 날짜로 읽어 지난 상품이 통과할 수 있는 경우는 1.1%(0.6~2.2%)이고, 이 중 절반은 차이가 7일 이내다. 나머지 2.3%는 실제보다 이른 날짜로 읽은 경우로, 판매 가능한 상품을 일찍 폐기하는 손실 쪽 오류다.

> 재확인 기준을 0.90에서 0.95로 높이면 지난 상품 통과 위험은 8건에서 2건으로 줄지만, 직원 검토 비율은 54.9%로 늘어난다. 매장의 안전 우선순위에 따라 기준을 조정할 수 있다.

> (조건) 이 수치는 개발 과정에서 사용한 사진이 포함된 701장과 대부분 미검수인 정답 라벨을 기준으로, 저장된 OCR 결과만으로 계산한 것이다.
